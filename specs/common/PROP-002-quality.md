# PROP-002: Качество и контроль ресурсов {#root}

Рабочую версию принимают по наблюдаемому поведению и выполненным проверкам. Кэш, DOM registry, сетевые запросы и локальные процессы должны иметь пределы и очистку.

## Проверки {#checks}

Для принятия интеграции: typecheck; lint без ошибок; unit/contract/DOM tests; production build Chrome; production build Firefox; проверка manifest, packaged permissions, CSP, названия и отсутствия секретов; браузерный smoke при доступном runtime. Непроведённый тест остаётся непроведённым. Реальный API без пользовательского ключа заменяется mock для автоматики, но mock не подтверждает смысловую точность перевода или реальный провайдерный доступ.

## Ресурсы {#resources}

- Конкурентность API по умолчанию 2; допустимый диапазон 1–4; максимум 40 узлов/10 000 символов на batch, обычный ориентир страницы 16 узлов/3 000 условных символов с весом CJK 3. Timeout 25 s на HTTP попытку; общий бюджет batch с retries/recovery — `min(300 000, (timeoutMs × 3 + 10 000) × 7)` ms. Response и собранный результат ограничены 1 MiB.
- DOM registry максимум 5 000 узлов; удалённые узлы освобождаются; таймеры/observers/listeners освобождаются в dispose и на завершении сессии. При превышении лимита пользователь видит объяснение, а не бесконечную нагрузку.
- Кэш: IndexedDB, TTL 30 дней, максимум 10 000 записей и 50 MiB оценённого UTF-8 payload; LRU prune на записи/старте; stats и clear работают без API. Нет ключей, полного DOM и сырых provider responses.
- Model discovery: ограниченный список и TTL 15 минут, максимум 1 000 моделей, не обязательный для ввода ID.
- Очереди, in-flight dedup и snapshots имеют конечную жизнь. Отмена и закрытие вкладки освобождают state. Восстановление оригинала прекращает автоперевод новых узлов до повторного режима перевода.
- Vitest максимум 2 worker. Установка зависимостей одна. Не оставлять watch/server/helper после приёмки, если пользователь ими не пользуется. Использовать собственные PID/пути, не останавливать чужие процессы.

## Проверка памяти и дублей {#hygiene}

На контрольных этапах координатор фиксирует размер node_modules/.wxt/.output, число локальных helper-процессов и доступную RAM. В runtime tests проверяется очистка registry и observers, ограничение кэша, дедупликация повторных запросов, отсутствие цикла мутаций. Не выдавать размер working set за доказательство отсутствия утечек: нужна повторяемая lifecycle-проверка. Производные папки исключены из Git; исходники и история не дублируются.

## Дизайн и доступность {#ui}

Светлая/тёмная тема проверяются отдельно; клавиатурный доступ, подписи полей, aria-live progress/error, reduced motion. Контраст обычного текста 4.5:1. Не тянуть CDN/script/font и не добавлять фиктивную статистику. Настройки ясно говорят, что ключ сохраняется локально без обещания аппаратного шифрования.
