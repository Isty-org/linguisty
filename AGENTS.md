# Linguisty: вход для разработки

Workflow mode: standalone

Перед изменениями прочитай `specs/protocols/BOOT.md`, свой WI, управляющие спеки и относящийся к задаче код. Полный источник продукта: `NEURAL_PAGE_TRANSLATOR_PLAN.md`; визуальный источник: `DESIGN.md`. Их трактовка для Linguisty закреплена в `specs/`. Важнее всего текущие указания пользователя.

## Инструкции пользователя

- Не смягчай факты. Не называй непроверенное успешным.
- При изменениях сообщай в чат текстом «было → стало».
- Перед поиском собственного решения исследуй интернет, Reddit, Stack Overflow и другие форумы; технические решения проверяй по официальной документации. Проверенные отправные точки находятся в `docs/RESEARCH.md`.
- Проверяй кэш, дубли и использование памяти в промежуточные этапы и после основной задачи. Чужой кэш и чужие процессы не удаляй.
- Продукт называется **Linguisty**. Первая версия поддерживает **Chrome и Firefox desktop**.
- Нет нашего сервера, телеметрии или общего API-ключа. Пользователь использует свой ключ или, по поручению 2026-10-08, Codex с входом ChatGPT. Новый UI предлагает только Codex и API-провайдеры; токены Codex только в памяти отдельной вкладки. Канон: `specs/modules/platform/INFRA-004-codex-connection.md`.

## Параллельная работа

Пользователь разрешил координатору создавать чаты `gpt-6.1-sol` с `thinking=max`, давать им задания и контролировать реализацию. Все чаты работают в этой папке. Не создавай дополнительные чаты самостоятельно.

- Каждый исполнитель меняет только пути, назначенные в его WI. Если нужен чужой файл, укажи точную необходимость в своём Result/ответе; координатор согласует изменение.
- Общие контракты `src/shared/contracts.ts`, настройки сборки, зависимости, `README.md`, канон, `BOARD.md`, `WAL.md`, `.me` и архив WI меняет только координатор. Не переписывай общие файлы и не делай массовое форматирование.
- Исполнитель обновляет Result своего WI, но не архивирует файл и не редактирует доску. Архивирование и принятие результата делает координатор после проверки.
- Не запускай свою установку зависимостей: используется одна общая `node_modules` и один `package-lock.json`. Сообщи о недостающей зависимости.
- У тестов максимум два worker; не держи watch-процессы после проверки. Не запускай платные запросы без предоставленного пользователем ключа и конкретного тестового поручения.
- Отсутствие чужого модуля во время параллельной работы не повод создавать его дубль. Работай по контрактам, запиши интеграционную зависимость.
- Добавляй `@spec spec://...#anchor` на точки ответственности и прямые тесты контракта. Одношаговая локальная правка не требует нового WI.

## Готовность

Для принятия версии нужны typecheck, lint, осмысленные тесты, сборки обеих платформ, проверка manifest/секретов/ресурсов и проверка браузерного сценария в доступном окружении. Реальная языковая точность через OpenRouter, если нет ключа, остаётся явно непроверенной. Политика: `specs/common/PROP-002-quality.md`.
