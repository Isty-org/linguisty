# План разработки Linguisty

Цель первого выпуска — полный пользовательский сценарий перевода страниц в **Firefox и Chrome**, OpenRouter/BYOK и OpenAI-compatible, без нашего сервера. План основан на исходных материалах; последовательность интеграции сохранена, независимые внутренние модули разрабатываются параллельно по закреплённым контрактам.

## Волны

| Волна | Работа | Результат и условие перехода |
|---|---|---|
| 0 | WI-001, WI-002 | Документы, ownership, общие типы, инструменты и одна установка зависимостей |
| 1, параллельно | WI-003…WI-008 | Storage/cache, engine/providers, page DOM, background, UI, fixtures/manifest checks/assets |
| 2 | WI-009: координатор + назначенные исправления в тех же WI | Соединённый pipeline; исправления конфликтов и ошибок по результатам интеграции |
| 3, параллельная приёмка | WI-008, WI-010 и финальная проверка координатора | Typecheck, lint, contract/DOM tests, обе сборки, Chromium и Firefox runtime, отчёт и hygiene |

Не путать параллельную разработку модулей с преждевременным внедрением future features. Native provider adapters из более поздних milestones не реализуются одновременно с MVP. Корректность общего контракта важнее количества открытых чатов.

## Зависимости

```text
WI-001 → WI-002 → ┬ WI-003 Storage ────────┐
                 ├ WI-004 Engine ────────┤
                 ├ WI-005 DOM ──────────┼→ WI-006 Background → Integrated smoke
                 ├ WI-007 UI ───────────┤
                 └ WI-008 QA/assets ────┴→ Acceptance / artifacts
```

Волна 1 начинается после создания shared/contracts; каждый модуль пишет собственные tests. Фон может писать обработчики до появления implementation зависимостей, импортируя закреплённые interfaces. QA готовит независимые fixtures/assets/checks, затем проверяет живой pipeline после интеграции. WI-010 независимо проверяет установленный Firefox во временном профиле: Chromium smoke не подтверждает Firefox runtime.

## Координация

Исполнители текущего прохода 2026-10-12 — отдельные локальные чаты **gpt-6-sol / max**, независимый аудитор — **gpt-6-astra / high**, как прямо поручил пользователь. Прежние волны выполнялись на gpt-6.1-sol / max. Координатор задаёт WI и разрешённые пути, смотрит результаты и статус через wait_threads, проверяет код, возвращает конкретные дефекты тому же исполнителю. Новые чаты нужны только для реально независимого результата. Общие файлы и lockfile не редактируются одновременно.

Текущий проход: WI-029 устраняет общую загрузку всех словарей, WI-030 исправляет recovery локальных данных, WI-031 проверяет версию 0.4.7. После реализации и приёмки WI-032 проводит независимый аудит; его подтверждённые findings получают отдельные WI исправлений на Sol/max и повторную проверку. Фактические статусы — только в BOARD.

## Контрольные точки

1. До запуска: новые требования отражены, все WI и ссылки существуют, imports известны.
2. После модулей: результаты и tests просмотрены, secrets boundary сохранён, нет дублей API/types, bounded queues/cache/memory.
3. После соединения: фон и страница работают с одинаковыми messages, остановка/restore проверены.
4. Перед завершением: checks выполнены; artifacts и установка доступны; фактические ограничения прямо указаны.

Настройка платного аккаунта, реальная языковая оценка без ключа и публикация в stores не заменяются фиктивным success.

## После локальной версии 0.1.0

1. Живая языковая оценка на пользовательском OpenRouter: французская недвижимость, числа/площади/названия, несколько моделей, время и стоимость; native toolbar/activeTab и installation consent.
2. Затем независимые продуктовые задачи: bilingual/selection/context menu, native provider adapters, glossary и per-site auto translate. Перед каждой — отдельный канон, WI и проверяемый сценарий.
3. Подпись Firefox и публикация магазинов — отдельный выпуск после подготовки listing/privacy материалов и прямого поручения пользователя.

Волны 0–3 реализованы; фактические результаты и ограничения — в [QA report](QA-REPORT.md) и [BOARD](../specs/BOARD.md). Эти следующие этапы не запущены автоматически.
