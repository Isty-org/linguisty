# Разработка и установка Linguisty

## Окружение

Node.js 22.12+ либо 24+ и npm. Chrome 120+ или Firefox 142+ desktop. Windows PowerShell: при блокировке npm.ps1 используйте `npm.cmd`. Одна установка зависимостей в корне. Сборку и общие конфиги меняет координатор.

```text
npm install
npm run dev:chrome
npm run dev:firefox
npm run typecheck
npm run lint
npm test
npm run build:chrome
npm run build:firefox
npm run check:manifests
npm run zip:chrome
npm run zip:firefox
```

`dev` запускается только для интерактивной отладки; для приёмки нужны production builds. Не оставлять лишние watch-процессы.

Первый GitHub-релиз сохраняет текущую версию **0.4.9**: [страница выпуска](https://github.com/Isty-org/linguisty/releases/tag/v0.4.9). Пакеты — `.output/linguisty-0.4.9-chrome.zip` и `.output/linguisty-0.4.9-firefox.zip`; в release assets также публикуется `SHA256SUMS.txt`. Для готового ZIP сначала распакуйте архив, затем используйте установку ниже. Firefox ZIP не подписан. Полные исходники, включая тесты, доступны через GitHub Source code по tag `v0.4.9`; из корня выполнить `npm ci`, затем `npm run build:chrome` или `npm run build:firefox`. Локальная `.me`, credentials, результаты тестов и кэш в исходники не входят. Автор и владелец разработки — Никита Цыжман ([@tsyzhman](https://github.com/tsyzhman)); [AUTHORS](../AUTHORS.md).

Исторические проверки: [QA-2026-10-13](QA-2026-10-13.md), [QA-POPUP](QA-POPUP.md), [QA-SUBSCRIPTION](QA-SUBSCRIPTION.md), [QA-CODEX](QA-CODEX.md). Проверки первого опубликованного выпуска фиксируются отдельно в [QA-RELEASE-2026-10-20](QA-RELEASE-2026-10-20.md).

## Chrome

Соберите `build:chrome`. Откройте chrome://extensions, включите режим разработчика, «Загрузить распакованное расширение», выберите `.output/chrome-mv3`. Закрепите Linguisty. После пересборки нажмите перезагрузку расширения и обновите проверяемую страницу.

## Firefox

Соберите `build:firefox`. Откройте about:debugging#/runtime/this-firefox, «Загрузить временное дополнение», выберите `.output/firefox-mv3/manifest.json`. Временное дополнение исчезает после перезапуска Firefox. Постоянная установка требует подписи Mozilla; она не входит в локальную разработку.

**Сохранение ключа и обновления.** Для повседневной работы устанавливайте подписанный Mozilla XPI через `about:addons` → «Установить дополнение из файла». Подписать пакет можно для самостоятельного распространения (unlisted), без публичного размещения в каталоге. Новые версии должны сохранять ID `linguisty@isty.local`; устанавливайте обновление поверх прежней версии, без удаления расширения. Режим «Сохранить на этом устройстве» использует browser.storage.local и переживает перезапуск/обновление в том же профиле. После сохранения парольное поле остаётся пустым: смотрите текст «Ключ сохранён: на этом устройстве».

При временной установке Firefox может удалить storage.local вместе с дополнением при завершении браузера. Код расширения не может запретить это. Для разработки Mozilla документирует `extensions.webextensions.keepStorageOnUninstall=true` и `extensions.webextensions.keepUuidOnUninstall=true`; эти настройки действуют на весь выбранный профиль и оставляют данные после удаления дополнений. Используйте отдельный тестовый профиль и устанавливайте значения вручную только если это требуется для разработки. Linguisty не меняет эти preferences. Это не превращает temporary install в постоянную установку.

Источники: [Mozilla: restart testing](https://extensionworkshop.com/documentation/develop/testing-persistent-and-restart-features/), [storage.local](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/local), [подпись и распространение](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).

## Настройка перевода

В options укажите OpenRouter или OpenAI-compatible URL, свой API-ключ, ID модели и языки. Сохраните с разрешением выбранного API-origin. Ключ можно помнить до конца browser session либо на этом устройстве. Пустое поле при следующем открытии означает, что сохранённый ключ скрыт. Для удаления есть отдельное действие.

На HTTP(S) странице откройте popup и переведите. Служебные browser pages/PDF/iframe content могут быть недоступны; интерфейс сообщает ограничение. Отмена сохраняет уже переведённый текст. «Оригинал» и «Перевод» переключают сохранённые Text nodes без API.

В 0.2.0 «Показывать перевод постепенно» включено по умолчанию. Если API возвращает SSE, целые проверенные фразы появляются раньше окончательного ответа; предварительный текст откатывается при отмене/ошибке и не кэшируется. Снятие флажка возвращает обычный запрос. API, который возвращает обычный JSON при stream=true, продолжает работать. Автоматическое повторение без stream разрешено только при явной ошибке неподдерживаемого параметра; иначе переключите режим вручную. Поддержка конкретной модели проверяется у вашего сервиса.

Журнал ошибок находится в отдельном разделе настроек. Он показывает очищенные доступные сведения сервиса, хранит до 100 записей 7 дней и позволяет скопировать или очистить только журнал. Обновления страницы/запросы и API-ключ в журнал не сохраняются.

## Проверки без ключа

В настройках можно выбрать **Подписка ChatGPT → Подключить ChatGPT**. Отдельная вкладка содержит четыре шага входа через ChatGPT, выбор модели, проверку и отключение. Её нужно оставить открытой. Установка CLI/host не требуется; API-режим сохраняет прежнее поведение. Инструкция и ограничения реального preview — [CODEX-CONNECTION](CODEX-CONNECTION.md).

Unit/DOM/API contract tests используют mock fetch и локальные fixtures. Они проверяют работу кода, cancellation и структуру ответа. Они не подтверждают фактическую точность французско-русского перевода. Живой тест описан в [TESTING](TESTING.md).
