The isolated browsers selected `ru`; Resource Timing did not show module imports. The harness was corrected: it permits eager `en/ru`, uses `BrowserContext.on('request')` events for Chromium, and does not present missing Firefox entries as a request measurement. Final run: 2 PASS; the earlier failures are not called successes.

## Unverified items and limits of the conclusion

- Real OpenRouter on an external French website, language accuracy, preservation of numbers/terms by a live model, and actual API speed are not established without the user's key and a specific paid test. Browser smoke establishes the local fixture and pipeline.
- Real Sign in with ChatGPT, plan availability, a live Luna 6 response, signed Firefox installation, publication, and the user's Chrome toolbar/permission dialog are unverified. Mock OAuth/Responses do not replace those results.
- In Firefox WebDriver, Resource Timing showed only static links: the number of dynamic locale chunks actually requested was not measured separately. The Firefox package contains 28 chunks; German/French UI and the local French pack work offline; only Chromium has a direct loading counter.
- Tests on the actual minimum supported browser versions, Chrome 120/Firefox 142, and a full WCAG/native-speaker audit were not performed.

The method was checked against the [official Playwright extension runtime guide](https://playwright.dev/docs/chrome-extensions), [network events and routing](https://playwright.dev/docs/network), [Vite dynamic imports](https://vite.dev/guide/features.html), and [Mozilla temporary add-on workflow](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Your_first_WebExtension).
